# Sensitive Data Exposure Total 19 Hacking Challenges
Sensitive Data Exposure occurs when an application improperly protects sensitive information such as passwords, credit card numbers, personal data, or API keys. Attackers can exploit this to steal data or impersonate users. Proper handling includes encryption, secure storage, and limited exposure.

**Examples in OWASP Juice Shop:**

* Exposed API keys or passwords in source code
* Unencrypted data in local storage or cookies
* Visible sensitive information in error messages or responses

**Tips to Solve:**

* Inspect the **frontend source code**, browser **local storage**, and **cookies**.
* Check **network requests** in developer tools for exposed data.
* Look for hidden fields, debug info, or configuration files revealing sensitive information.

# 1. Exposed Metrics

> The Exposed Metrics challenge requires you to locate an endpoint that provides application usage data intended for monitoring systems. When improperly exposed, this endpoint can reveal internal operational details, which attackers could leverage.

**Steps to Access and Solve:**

1. Open the application in your browser.
2. Navigate to or directly request the **metrics endpoint**:

   ```html
   http://10.30.30.145:3000/metrics
   ```
3. Inspect the returned data for system metrics like request counts, error rates, or other internal statistics.
4. If needed, use hints from **Prometheus documentation** for understanding metrics format:
   [Prometheus First Steps](https://prometheus.io/docs/introduction/first_steps/)

**Vulnerable Parameter:**

* None required; the endpoint itself is publicly accessible.

**Tip:**

* Metrics are usually plain text and can be scraped by monitoring tools.
* Accessing this endpoint correctly in Juice Shop will mark the challenge as solved.
