
# Improper Input Validation – 12 Hacking Challenges

Improper Input Validation is a vulnerability that occurs when a web application fails to properly check, validate, or sanitize user input. In other words, the application **blindly trusts whatever the user sends** — whether it’s form data, query parameters, or API requests.

### Attackers exploit this to:

* Bypass intended logic (e.g., duplicate registrations).
* Inject malicious payloads (SQL, XSS, Command Injection).
* Access hidden files or parameters.
* Escalate privileges or leak sensitive data.

### **Impact:**
* Improper input validation can lead to data breaches, unauthorized access, privilege escalation, and in some cases, complete application compromise.

# 1. Repetitive Registration
> Repetitive Registration is a vulnerability that occurs when a web application allows the same user to register multiple accounts using identical details (e.g., same email, username, or phone number). This usually happens because the backend does not enforce uniqueness checks, leading to duplicate accounts and potential abuse.

* Task = Follow the DRY principle while registering a user.

**Steps to Access:**

1. Go to **Registration – New User**.
2. Capture the request in **Burp Suite**.
3. Send the request to **Repeater**.
4. Remove the parameter **`passwordRepeat`**.
5. Send the modified request.

✅ **Successfully completed task**

# 2. Zero Stars
> This challenge demonstrates **Broken Input Validation** and **Parameter Tampering**. The app tries to restrict user ratings between 1–5 stars, but the rating parameter is only validated client-side. By intercepting and modifying the request, attackers can bypass the restriction and give an invalid rating (e.g., 0 stars).

**Task:**
> Submit a **zero-star feedback** to the store.

**Steps to Complete Task:**
1. Open the website menu → **Customer Feedback**.
2. Fill in details:
   * Comment = `hello`
   * Rating = `2`
   * Solve Captcha → **Submit**.
3. Turn **BurpSuite Intercept ON**.
4. Capture the **POST Request** containing the rating value.
5. Send the request to **Repeater**.
6. Modify the `rating` parameter:
   ```http
   rating=0
   ```
7. Forward the request.
8. ✅ Rating successfully submitted as **Zero Stars**.

# 3. Missing Encoding
> Missing Encoding vulnerability occurs when special characters in a URL (like `#`, `?`, `&`) are not properly encoded. As a result, the browser misinterprets them (e.g., treats `#` as an anchor) and does not send the correct request to the server.

* **Task:** Retrieve the photo of **Bjoern's cat** in *"melee combat-mode"*.

**Steps to Access:**

1. Open → **Dashboard** → Press **Ctrl+Shift+I** (Inspect).
2. Go to the **Elements tab** → Locate the broken cat image entry.
3. You’ll find the image tag like this:

```html
<img src="assets/public/images/uploads/😼-#zatschi-#whoneedsfourlegs-1572600969477.jpg" 
     alt="😼 #zatschi #whoneedsfourlegs">
```

4. Problem → The `#` character is not encoded.

   * Browser interprets `#` as an anchor, so it never gets sent to the server.

5. Fix → Replace `#` with its encoded value `%23`.

> Corrected URL:

```html
<img src="assets/public/images/uploads/😼-%23zatschi-%23whoneedsfourlegs-1572600969477.jpg" 
     alt="😼 #zatschi #whoneedsfourlegs">
```

6. Open this corrected URL in the browser:

```
http://10.30.30.145:3000/assets/public/images/uploads/😼-%23zatschi-%23whoneedsfourlegs-1572600969477.jpg
```
> The cute cat photo will now display 🐱

✅ **Successfully completed task!**

# 4. Deluxe Fraud
> Deluxe Fraud is a vulnerability where an attacker obtains a **Deluxe Membership (premium account)** without paying for it. This happens due to **broken payment validation**, where the application relies on client-side checks or a single parameter (like `paymentMode`) instead of securely verifying the transaction server-side.

* **Task:** Obtain a **Deluxe Membership** without paying for it.

**Steps to Complete Task:**
1. Go to **Dashboard → Side Menu → Deluxe Membership**
   or directly open:
   ```
   http://10.30.30.145:3000/#/payment/deluxe
   ```
2. Open **Developer Tools (Ctrl+Shift+I)** → go to **Elements Tab**.
3. Locate the **Pay 49.00 button** → it will be disabled.
   * Remove the `mat-raised-button...disabled` part.
   * Remove the attribute `disabled="true"`.
   * Now the button becomes clickable. 
4. Click the enabled **Pay 49.00** button.
5. Intercept the **POST request** in Burp Suite.
   * Original payload looks like:
     ```json
     { "paymentMode": "wallet" }
     ```
   * Change the value from `wallet` → `paid`.
6. Forward the modified request.

* **✅ Successfully Completed:** You obtained a **Deluxe Membership without paying**, solving the **Deluxe Fraud** challenge. 🎉

# 5. Payback Time

> The **Payback Time** challenge highlights a vulnerability in online payment systems where **improper input validation** allows attackers to manipulate the payment process. Instead of paying for items, attackers can exploit flaws in the checkout or coupon logic (e.g., entering negative values, altering price fields, or misusing discounts) to **receive money back or reduce the payable amount unfairly**.

* **Task:** Place an order that makes you rich.

**Steps to Complete Task:**
1. Login with a new user account and add this product to your basket:
   * *Melon Bike (Comeback-Product 2018 Edition)*
2. Go to **Basket → Checkout**.
   * Select an Address → Continue
   * Choose **One Day Delivery** → Continue
   * Select **Card Payment** → Continue
3. Open **Burp Suite** and capture the request:
   ```
   POST /api/Basket/Items/
   ```
   * Send it to **Repeater**.
   * Change the `quantity` value from `1` → `-100`.
   * Send the request.
4. Verify in the browser UI that the basket value has been altered.
5. Place the order → you’ll end up with a **negative total (profit instead of payment)**.

* ✅ You **successfully** solved a challenge: Payback Time (Place an order that makes you rich.)
