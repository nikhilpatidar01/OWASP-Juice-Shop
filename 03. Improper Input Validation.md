
# Improper Input Validation – 12 Hacking Challenges

Improper Input Validation is a vulnerability that occurs when a web application fails to properly check, validate, or sanitize user input. In other words, the application **blindly trusts whatever the user sends** — whether it’s form data, query parameters, or API requests.

### Attackers exploit this to:

* Bypass intended logic (e.g., duplicate registrations).
* Inject malicious payloads (SQL, XSS, Command Injection).
* Access hidden files or parameters.
* Escalate privileges or leak sensitive data.

### **Impact:**
* Improper input validation can lead to data breaches, unauthorized access, privilege escalation, and in some cases, complete application compromise.

# 1. Repetitive Registration
> Repetitive Registration is a vulnerability that occurs when a web application allows the same user to register multiple accounts using identical details (e.g., same email, username, or phone number). This usually happens because the backend does not enforce uniqueness checks, leading to duplicate accounts and potential abuse.

* Task = Follow the DRY principle while registering a user.

**Steps to Access:**

1. Go to **Registration – New User**.
2. Capture the request in **Burp Suite**.
3. Send the request to **Repeater**.
4. Remove the parameter **`passwordRepeat`**.
5. Send the modified request.

✅ **Successfully completed task**

# 2. Zero Stars
> This challenge demonstrates **Broken Input Validation** and **Parameter Tampering**. The app tries to restrict user ratings between 1–5 stars, but the rating parameter is only validated client-side. By intercepting and modifying the request, attackers can bypass the restriction and give an invalid rating (e.g., 0 stars).

**Task:**
> Submit a **zero-star feedback** to the store.

**Steps to Complete Task:**
1. Open the website menu → **Customer Feedback**.
2. Fill in details:
   * Comment = `hello`
   * Rating = `2`
   * Solve Captcha → **Submit**.
3. Turn **BurpSuite Intercept ON**.
4. Capture the **POST Request** containing the rating value.
5. Send the request to **Repeater**.
6. Modify the `rating` parameter:
   ```http
   rating=0
   ```
7. Forward the request.
8. ✅ Rating successfully submitted as **Zero Stars**.
