# Broken Authentication - Total 7 Hacking Challenges

**Definition:**
Flaws in authentication that allow attackers to **bypass login, hijack accounts, or steal credentials**.

**Causes:**
* Weak or default passwords
* Predictable session IDs
* Poor password reset mechanisms
* No MFA

**Impact:**
* Account takeover
* Unauthorized access
* Data breach

**Examples:**
* Login bypass
* Session hijacking
* Brute-force attacks

---

# **1. Password Strength**

> Password Strength refers to how resistant a password is to being guessed or cracked. Strong passwords are long, complex, and unpredictable, using a mix of letters, numbers, and special characters.

* **Task:-** Log in with the administrator's user credentials **without changing them or using SQL Injection**.

**Vulnerable Parameter:-** User Login

**Credentials:**
```text
Email: admin@juice-sh.op
Password: admin123
```
**How It Was Done:**
1. Open the login page.
2. Enter the administrator’s credentials exactly as provided.
3. Submit the form to log in successfully.

* **✅ Task Completed:**- Successfully solved the challenge: Password Strength (logged in with the administrator's credentials without changing them or using SQL Injection).

# 2. GDPR Data Erasure

> Under the **GDPR (General Data Protection Regulation)**, **Data Erasure** (also called the *Right to be Forgotten*) means that a person can ask a company to permanently delete their personal data when it is **no longer needed** or if they **withdraw consent**.
> 👉 In short: **GDPR Data Erasure = Your right to ask companies to delete your personal data.**

* **Task** Log in with **Chris' erased user account**.

* **Vulnerable Parameter**

* **User Login** (SQL Injection vulnerability in the login form).

* **Credentials Used**

```text
chris.pike@juice-sh.op'--
123
```

* **Steps to Complete Task**

1. Open the **Login Page** of Juice Shop.
2. In the **Email field**, enter the following payload:

   ```
   chris.pike@juice-sh.op'--
   ``` 
 > (This SQL Injection payload comments out the rest of the query, bypassing authentication).

3. In the **Password field**, type anything (e.g., `123`).
4. Submit the login form.
5. You will successfully log in as **Chris**, even though his account was supposed to be erased.

* **✅ Task Completed:-** GDPR Data Erasure (Logged in with Chris' erased user account).
