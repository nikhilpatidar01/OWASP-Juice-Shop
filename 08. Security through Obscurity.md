# Security through Obscurity -  Total 3 Hacking Challenges

**Security through obscurity** is a weak security practice where a system or application relies on **secrecy of its design, code, or implementation** to stay secure—rather than using strong, tested, and layered security controls.

For example:
* Hiding an admin panel by naming it `admin123hidden.php` instead of implementing proper authentication.
* Using proprietary algorithms instead of standard encryption.
* Relying on secrecy of configuration rather than actual security controls.

**Why it’s bad:**
* Once the “secret” is discovered (through reverse engineering, guessing, or leaks), the system becomes completely vulnerable.
* It gives a **false sense of security** instead of true protection.

> 👉 In short: **Obscurity ≠ Security.** It can be used as an *extra layer*, but never as the *only defense*.

# 1. Privacy Policy Inspection

> The **Privacy Policy Inspection** challenge shows how sensitive or hidden information can sometimes be disclosed through a website’s **Privacy Policy or other legal documents**. Developers may unintentionally leave technical details, test accounts, or hints about the application’s internal functionality in these documents. Attackers can exploit this information to gain access to accounts, discover hidden features, or perform other attacks.

* **Task:** Prove that you actually read the Privacy Policy.

* **Vulnerable Parameter:** `Privacy-Policy`

**Steps to Complete Task:**
1. Open the URL:
   ```
   http://localhost:3000/#/privacy-security/privacy-policy
   ```
2. Hover your mouse over each paragraph → you’ll notice a **fire-effect** on certain words or sentences.
3. Open **Developer Tools → Inspect HTML**, then note down all text inside:

   ```html
   <span class="hot"> ... </span>
   ```
   The hidden words are:
   ```
   http://localhost, We may also, instruct you, to refuse all, reasonably necessary and responsibility
   ```
4. Combine them into a path:
   ```
   http://localhost:3000/we/may/also/instruct/you/to/refuse/all/reasonably/necessary/responsibility
   ```
   (add the server port if required).
5. Visit the constructed URL → this solves the challenge.

* **Note:** Even though the path is correct, you’ll only get a **404 Error**:
```
ENOENT: no such file or directory, stat '/app/frontend/dist/frontend/assets/private/thank-you.jpg'
```
> This means the challenge is solved, but there’s no actual reward image.

**✅ Successfully Completed:** You solved the challenge **Privacy Policy Inspection** → *Proved you actually read the Privacy Policy*.
