# Broken Access Control Total 11 Hacking Challenges

**Broken Access Control** happens when a website or app **doesn’t properly check what users are allowed to do**, letting them access things they shouldn’t.

**Examples:**

1. **URL Tampering (IDOR)**

   * URL: `https://shop.com/order?order_id=101`
   * A user changes it to `order_id=102` and sees someone else’s order details.

2. **Admin Page Access**

   * A normal user visits `https://shop.com/admin/dashboard` directly without being an admin and can see or change sensitive data.

3. **Privilege Escalation**

   * A user changes their role from `user` → `admin` in a request and suddenly has admin privileges.

**Key point:** The app **isn’t checking permissions properly**, so users can do things they shouldn’t.

# 1. View Basket
**View Basket** is the feature or page where a user can **see all the items they have added to their shopping cart** before proceeding to checkout.

**Vulnerability / Task Example:**
> An attacker may be able to **view another user's shopping basket** if access control is not properly enforced.

**Steps to Complete Task:**
1. **Login** as a user
2. Go to **Dashboard**
3. **Add items** to the basket
4. Access the basket page:

```html
http://10.30.30.145:3000/#/Dashboard
```

**Key Point:**
> Proper **access control** should prevent users from viewing or modifying baskets of other users.

# 2. Web3 Sandbox

> A **Web3 Sandbox** vulnerability occurs when a smart contract testing or development environment is unintentionally exposed in production. This allows attackers to interact with, deploy, or exploit contracts in a way that was never meant to be public.

**Task:**
> Find an accidentally deployed code sandbox for writing smart contracts on the fly.

**Steps to Complete Task:**
1. Go to **Dashboard**.
2. Press **Ctrl+Shift+I** (Inspect Element).
3. Navigate to the **Sources** tab.
4. Open **main.js** and search for the keyword:

   ```bash
   sandbox
   ```
5. Found the reference → **web3-sandbox**.
6. Accessed the endpoint:

```html
http://10.30.30.145:3000/#/web3-sandbox
```
✅ **Task Completed** — Accidentally deployed Web3 Sandbox discovered.

# 3. Admin Section

> This challenge highlights how sensitive application features (such as the admin panel) can be exposed when routes/endpoints are hardcoded in client-side JavaScript files without proper security. Attackers can discover these hidden sections by simply inspecting the source code.

* **Task:** Access the **administration section** of the store.

**Steps to Complete Task:**
1. Go to the **Dashboard**.
2. Use SQL Injection to log in as admin (example payload):
   ```
   ' OR 1=1--
   ```
3. Press **Ctrl+U** to view the page source.
4. Locate and open the **main.js** (JavaScript file).
5. Search for the keyword **administration** inside the file.
6. You’ll find the hidden admin route:
```bash
http://10.30.30.145:3000/#/administration
```
7. Open this URL in the browser to access the **Admin Section**.

* ✅ **Task Completed** You successfully solved a challenge: Admin Section (Access the administration section of the store.)

# 5. Forged Review

> A **forged review** is a fake review written by someone pretending to be a genuine customer. It’s not authentic feedback — instead, it’s crafted to **mislead others** into thinking a product/service is better or worse than it really is.

* **Task:-** Post a product review as another user **OR** edit any existing user’s review.


 **Steps to Complete Task**

1. **Login** as `admin@juice-sh.op`.
2. Choose **any product** and write a review.
3. Submit the review while keeping **BurpSuite intercept ON**.
4. Observe that a **PUT request** is sent for the review.
5. Send this request to **Repeater** in BurpSuite.
6. Modify the request body:

   * Change the `"author": "admin@juice-sh.op"` → `"author": "anonymous"` (or any other user).
7. Send the request again.
8. If you see `{"status":"success"}` in the response → Review forged successfully. ✅
9. Go back to the application and verify the review now appears under the **forged identity**.

* **✅ Task Completed:** Successfully completed when your review shows up as **another user’s review**.

# 6. Easter Egg

> In web applications, an **Easter Egg** is a hidden feature, message, or functionality intentionally placed by developers, often as a secret or inside joke, which is not part of normal application use.

* **Task:** Find the hidden Easter Egg.

**Steps to Solve:**

1. Navigate to `http://10.30.30.145:3000/ftp`.
2. Locate the file named `eastere.gg`.
3. Download the file `eastere.gg%2500.md`.

   * Here `%2500` decodes to `%00` (null byte).
   * The **null byte injection** bypasses the file extension filter, tricking the server into treating it as `eastere.gg` instead of blocking it due to `.md`.

**Result:** ✅ Task completed when the hidden Easter Egg is discovered and confirmed in the downloaded file.

**Short Note (Exam-Ready):**
> Easter Egg = Hidden feature in an app. In Juice Shop, accessed by downloading `eastere.gg%2500.md` using null byte injection to bypass extension checks.
